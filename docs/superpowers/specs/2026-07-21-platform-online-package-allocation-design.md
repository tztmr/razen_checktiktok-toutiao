# 抖音与头条在线包分开分配设计

## 目标

把当前统一的“分配在线包”拆成独立的抖音和今日头条在线包分配。抖音在线 ZIP 输出到源目录下的 `douyin_online/`，头条在线 ZIP 输出到源目录下的 `toutiao_online/`。掉线包、正常功能包和限制功能包的现有行为保持不变。

## 用户交互

“包分配”区域用以下两个按钮替换现有“分配在线包”按钮：

- `分配抖音在线包`
- `分配头条在线包`

两个按钮分别显示独立的执行中状态。对应平台没有在线 ZIP、批量检测正在运行或应用不在 Tauri 运行时中时，按钮不可用。成功、部分失败和完全失败继续通过现有工作台状态行反馈。

## 分配规则

分配以源 ZIP 路径为单位，不以账号行数量为单位。同一个 ZIP 因抖音多账号展开成多行时只处理一次。

先从当前批量结果计算两个去重集合：

- 抖音在线集合：`appType === "douyin" && status === "online"`
- 头条在线集合：`appType === "toutiao" && status === "online"`

然后按以下规则生成分配计划：

1. 只在抖音在线集合中的 ZIP 移动到 `douyin_online/`。
2. 只在头条在线集合中的 ZIP 移动到 `toutiao_online/`。
3. 同时存在于两个在线集合中的 ZIP 不移动源文件；点击任一平台分配按钮时，将源 ZIP 复制到该平台目录。两个按钮都执行后，两个目录各有一份，原始 ZIP 仍保留。

保留双平台 ZIP 的原文件是刻意设计：两个按钮可以按任意顺序执行，不会出现第一个按钮移动文件后，第二个按钮找不到源文件的问题。

## 代码边界

新增一个前端纯逻辑模块，负责根据批量行生成平台在线包分配计划。输入只包含 `sourceZip`、`appType` 和 `status`，输出包含当前平台的移动路径和复制路径。React 组件只负责触发计划、调用 Tauri 命令并显示状态，不在事件处理器中重复集合运算。

后端保留现有 `move_zip_files` 命令，并允许 `douyin_online`、`toutiao_online` 两个新目标目录。新增 `copy_zip_files` 命令，复用 ZIP 文件校验、目标目录白名单和部分失败汇总规则，但使用文件复制而不是重命名。

复制命令只接受明确允许的目标子目录，拒绝绝对路径、父目录跳转和非 ZIP 文件。目标文件已经存在时返回明确错误，不覆盖已有文件。

## 数据流

点击某个平台分配按钮后：

1. 前端使用全部 `batchRows` 计算两个平台的在线 ZIP 集合。
2. 当前平台独有的 ZIP 调用 `move_zip_files`。
3. 两个平台共有的 ZIP 调用 `copy_zip_files`。
4. 前端汇总移动与复制结果，写入现有状态行。
5. 任一后端调用失败时，保留另一调用的真实结果，不显示虚假的整体成功。

## 错误与重复操作

- 源文件不存在、不是 ZIP、目标目录无法创建或目标文件已存在时，后端返回具体错误。
- 一组文件部分成功时，状态行同时显示成功数和失败原因。
- 重复点击可能遇到源文件已移动或目标副本已存在；界面必须如实显示该状态，不覆盖文件，也不把它报告为新的成功。
- 双平台冲突只由在线结果集合的交集判断，不根据文件名或 APP 显示名称猜测。

## 测试与验证

TypeScript 测试覆盖：

- 抖音在线行只进入抖音计划。
- 头条在线行只进入头条计划。
- 掉线、失败、待检测和跳过行不进入在线计划。
- 同一平台的多账号行按 `sourceZip` 去重。
- 同一 ZIP 同时在线时，两个平台计划都把它标记为复制而不是移动。

Rust 测试覆盖：

- 新目录在白名单内，任意其他目录被拒绝。
- 复制保留源 ZIP 并创建目标 ZIP。
- 已存在的目标不被覆盖。
- 非 ZIP 路径被拒绝。

完成前执行：

```bash
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri build -- --bundles app
```

最终产物仍为 `src-tauri/target/release/bundle/macos/iOS Sandbox ZIP Reader.app`。在打包应用中确认两个按钮可独立执行，并核对实际生成的 `douyin_online/` 与 `toutiao_online/` 目录。

## 不在本次范围

- 不拆分掉线包、正常功能包或限制功能包。
- 不修改抖音或头条在线状态判定逻辑。
- 不自动删除同时属于两个平台的原始 ZIP。
- 不覆盖目标目录中已经存在的同名 ZIP。
